## Milestone 4: Lazy DFA

Status: done

The prefilter benchmark measured 1.266 s at one thread and 0.413 s at four
threads, versus 0.179 s for Rust `regex` bytes. The prefilter is necessary but
not sufficient, so the lazy DFA is now required. Add lazily determinized
states over code-point equivalence classes, a bounded state cache, PikeVM
fallback on overflow, and anchored PikeVM for captures. Keep the first-unit
prefilter as the candidate selector. Acceptance criteria are in
`spec/docs/milestones.md`.

References: ADR-0002, ADR-0005, ADR-0006, ADR-0010

### Done

- Added `src/dfa.rs` with:
  - Equivalence-class boundaries from every literal and class range.
  - Class maps for UCS-1 (256 entries), UCS-2 (65,536), and UCS-4 (0x110000).
  - Lazy DFA states holding consuming instructions, pending end assertions,
    and a match flag, all in priority order.
  - Leftmost-first match tracking: the first `Match` prunes lower-priority
    states; later higher-priority matches override the end.
  - `Start` resolved from position zero; `End` kept pending until the final
    position.
  - A bounded state cache in `Scratch`, with overflow fallback to the PikeVM.
- Integrated the DFA into `pikevm::find`: patterns with a safe first-unit set
  use the prefilter plus the DFA; every other pattern, overflow, or
  out-of-contract unit falls back to the PikeVM.
- Added DFA unit tests comparing it with the PikeVM on alternation priority,
  greedy repetition, optional prefixes, `^`, `\A`, `\Z`, impossible assertion
  placements, UCS-2, and UCS-4. Added class-map and cache-overflow tests.
- Added ADR-0011 and updated `architecture.md`, `benchmarks.md`,
  `milestones.md`, `testing.md`, `conventions.md`, `index.md`, `README.md`,
  and `plan.md`.
- Removed milestone 4 from the plan and raised milestone 5 (PyO3 binding and
  end-to-end benchmark) to priority 4.

### Results: full corpus, 1M posts, 334,136 mentions

Machine: Intel Core i5-8350U, 8 logical cores, Linux, Rust 1.97.1. Median of
three engine-only runs.

- PikeVM, 1 thread: 5.424 s.
- Prefilter, 1 thread: 1.266 s; 4 threads: 0.413 s.
- DFA, 1 thread: 0.360 s; 4 threads: 0.110 s.
- Rust `regex` bytes, 1 thread: 0.169 s; 4 threads: 0.061 s.
- Rust `regex` str, 1 thread: 0.185 s; 4 threads: 0.061 s.

The DFA is about 3.5 times faster than the prefiltered PikeVM. It is about
2.1 times slower than the bytes baseline at one thread and 1.8 times slower at
four threads. It does not beat the same-thread baseline. The remaining gap is
in per-candidate DFA setup and transition lookup, not in the class scan.

Correctness: 8 unit tests and 15 integration tests pass. The randomized
Python differential ran 40,414 cases with zero mismatches. DFA and PikeVM
results also agree on the targeted assertion and UCS-2/UCS-4 cases.

### Spec/ADR amendments

- [open] The DFA fast path requires a safe first-unit set. Patterns with broad,
  negated, or nullable first sets remain on the PikeVM. If uniform DFA
  coverage is required, add unanchored start-state handling.
- [acted] The transition cache used a hash map. It is now a dense per-state
  row keyed by equivalence class, with a cell cap and fallback.
- [open] Class maps cost about 2.4 MB per scratch. Share them across threads if
  the Python binding creates many scratches.
- [open] Word boundaries and flags arrive in milestone 2. The DFA must either
  learn their context or route those patterns to the PikeVM; it must not
  assume they are absent.
- [open] The benchmark still reports one total time. Add per-kind timing to
  show whether UCS-4 posts dominate.
- [open] The full 1M-post benchmark remains unsuitable for ordinary CI.
